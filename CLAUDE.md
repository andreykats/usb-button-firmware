# USB Button Web Serial interface — CLAUDE.md

Branch `web-serial-interface`: the browser side of USB Button settings mode. The firmware
is on `ws-esp32s3-zero` (Waveshare ESP32-S3-Zero) and `ws-esp32s3-matrix` (Waveshare
ESP32-S3-Matrix, the same sketch with its own hardware layer), "Advanced" units only;
the Zero's sketch header is the source of truth for the settings protocol. README.md is for people using
or working on the page (compatible browsers, how to connect).

## Layout

```
index.html    ← settings page: static file, inline CSS/JS, no build step (published)
howto.js      ← the page's BOOT animations (three.js module, published)
models/esp32-s3-zero.glb ← the board for howto.js, generated by tools/step_to_glb.py (published)
vendor/three/ ← three.js 0.186.1, unmodified: only the files howto.js imports (published)
vendor/lucide/LICENSE ← for the hand icon inlined in index.html (published)
tools/step_to_glb.py ← Waveshare STEP model → models/esp32-s3-zero.glb (local only)
experiments/  ← scenes being tried out for other pages (local only, not published)
resources/    ← arcade button scene: saved copy of experiments/arcade.html and its renders (local only)
debug.html    ← debugger for the firmware's normal-mode WEB_SERIAL_ENABLED=1 protocol (local only)
serve.py      ← localhost server; python3 -I serve.py opens Chrome at http://127.0.0.1:8080
.github/workflows/pages.yml ← publishes index.html, howto.js, models/, vendor/ to GitHub Pages
```

## Deploy

- Every push to `web-serial-interface` that changes a published file or the workflow
  publishes them to https://button.drey.dev via GitHub Pages (Actions).
- After every change to a published file: commit and push `web-serial-interface` without
  asking (standing permission from the user), then confirm the run succeeded
  (`gh run list -R andreykats/usb-button-firmware -b web-serial-interface`) and that
  `curl -s https://button.drey.dev/ | shasum` matches the local file.
- The custom domain is set in the repo's Pages settings (no CNAME file with Actions
  deploys); DNS: CNAME `button.drey.dev` → `andreykats.github.io`; HTTPS enforced. Only
  `main` and `web-serial-interface` may deploy (github-pages environment rule).
- Web Serial needs a secure context: HTTPS, or localhost via serve.py.

## Connection

- Web Serial: `navigator.serial.requestPort()` filtered to the Advanced boards: Zero
  303A:822B and Matrix 303A:81FB (each the same in normal and settings mode), opened at
  115200. Never open at 1200 baud: that resets the
  board into its bootloader.
- `port.getInfo()` exposes only VID/PID; anything else the page shows (key, settings)
  must come from the firmware over the protocol. Chrome's chooser shows the USB product
  name, e.g. `USB Button [2] (EB:F4:58)`, but the page cannot read it.
- Previously granted ports connect automatically (`getPorts()` and the `connect` event)
  in quiet mode: a button in normal use doesn't answer `GET`, which is not an error.

## Settings protocol (newline-terminated text)

Page → board: `GET`, `SET:name=value`, `DEFAULTS`, `REBOOT` (restart into normal use;
the page's **Disconnect** button).
`SET:key=x` changes the key (a–z, 0–9; the "Key" panel, built from `KEY_ROWS`).
`DEFAULTS` leaves the key alone. Firmware older than this answers it with
`ERR:UNKNOWN_SETTING:key`, which the page shows as "update the button's firmware".
Board → page: `SETTINGS:name=value,…,key=x` (GET, DEFAULTS),
`OK:name=value`, `ERR:…`, `REBOOTING...`, and for the trigger test `TRIGGER:down|up`
and `TYPE:hold|tap`.

## Adding a setting

The firmware branch's CLAUDE.md sends agents here whenever a customizable feature is
added. For each new firmware setting (an entry in `SETTINGS[]` on `ws-esp32s3-zero`):

1. Add a `<fieldset data-setting="NAME">` with one radio per choice: `name="NAME"`,
   `value` = the firmware's choice name. Order the tiles as they read best (brightness
   is High / Normal / Low); the default is whatever the firmware lists first.
2. Add `NAME` to `SETTING_NAMES` in the script.
3. Settings an older firmware doesn't report are hidden (`showReportedSettings()`), so the
   page can be published before every board is reflashed.
4. Render it (headless Chrome screenshot), commit, push, and check the deploy (above).
5. Update README.md here if the change affects how the page is used.

## BOOT animations

Two panels show Waveshare's ESP32-S3-Zero acting out their steps, each a script in
`howto.js` run on its own copy of the board:

- Connect (`#howto`, `holdForSettings`): a hand holds BOOT 3 s with its index finger
  (a progress ring fills; the RGB LED stays green), the restart (LED off), then the
  settings-mode rainbow from purple.
- Change the key (`#howtoKey`, `pressForNextKey`): a quick press of BOOT, no ring; on
  release the LED flashes white and the keycap beside the board steps to the next key.
  The key carries on from loop to loop (1, 2, 3, …), as on the button. The panel is
  hidden while connected: in settings mode BOOT leaves settings mode.
- The two panels (and "Browser not supported") sit in `.intro`: side by side from a
  900 px window, the page widening to 1000 px while one shows; stacked below that.
  Connected, the page is back to 620 px.

No text over them, bar the keycap: the steps below say it. The hand is a flat outline
(Lucide's "pointer" icon, ISC, inline SVG in a `<template>` in `index.html` with a white
fill traced along its outline), cloned into each figure, drawn over the canvas and
placed in pixels from BOOT's projected position (`placeHand()`), turned to point right.
`howto.js` builds the scenes with three.js around the GLB and drives them with the
firmware's timings and its `colorWheel()`.

- `index.html` imports `howto.js` with `import()` only when Web Serial is available, so
  other browsers never fetch three.js (~460 KB gzipped). The `<script type="importmap">`
  maps `three` and `three/addons/` to `vendor/three/`.
- A figure stays hidden until its first frame renders; if WebGL or a file fails, the
  written steps stand alone. Each renders only while on screen. No pause button (the
  user's choice); with `prefers-reduced-motion` each shows a still frame of the press.
- Face-on view from straight above, USB-C at the top, like Waveshare's pinout drawing.
- Keep their timings in sync with the firmware: `SETTINGS_HOLD_MS`, `RAINBOW_PERIOD_MS`,
  `RAINBOW_START_POS`, `colorWheel()`, `COLOR_GREEN` (normal state when plugged in),
  `PRESS_FEEDBACK_MS` and `COLOR_WHITE` (flash after a BOOT release), `nextKeyChar()`
  (key order) and `DEFAULT_KEY`.
- The GLB's `boot` (BOOT plunger) and `led` (WS2812B) nodes are the animated parts;
  everything else is merged by material. Regenerate it with `tools/step_to_glb.py`
  (needs OCP; command in its docstring). Parts are recoloured there.
- Upgrading three.js: replace `vendor/three/` with the same files from the npm package
  (`npm pack three@<version>`) and update the version above. `**/build/` is git-ignored,
  so `vendor/three/build/` is excepted in `.gitignore`.
- Check them by stepping a fake clock: Playwright `page.clock.install()`, wait for the
  figures to show, `page.clock.pauseAt()` (an installed clock otherwise keeps running in
  real time), then `page.clock.runFor(ms)` and `page.screenshot({ clip })` of `#howto` /
  `#howtoKey` (element screenshots wait on animation frames and can time out).

## Conventions

- Copy is user-facing: plain verbs, sentence case; name controls by what they do.
- Lamp previews use the firmware's timings (breathe 3 s, fast 100 ms, slow 1 s); keep
  them in sync with the `LED_*_PERIOD_MS` constants.
- Respect `prefers-reduced-motion`; keep keyboard focus visible.
